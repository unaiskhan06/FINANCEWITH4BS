# Finance With 4B's - Setup & Usage Guide

## Configuration (.env)

All secrets live in a `.env` file at the project root. It is listed in `.gitignore`, so it is
never committed. `backend/app.py` loads it automatically via `python-dotenv`; real environment
variables (such as the ones set in the Render dashboard) always take priority over it.

Start from the template:
```bash
cp .env.example .env
```

| Key | Purpose |
|-----|---------|
| `FLASK_SECRET_KEY` | Signs admin session cookies. Generate with `python -c "import secrets; print(secrets.token_hex(32))"`. If unset, a random key is used and admin logins reset on every restart. |
| `FLASK_DEBUG` | `1` locally, `0` in production. |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | Admin panel login. The panel stays locked until both are set. |
| `DATABASE_URL` | Hosted database connection string. Takes priority over the `MYSQL_*` keys. `postgresql://...` selects PostgreSQL; `mysql://...` selects MySQL. |
| `MYSQL_HOST/PORT/USER/PASSWORD/DATABASE` | Local MySQL, used only when `DATABASE_URL` is empty. |
| `MYSQL_SSL` | `1` forces TLS on a MySQL connection (automatic for non-localhost hosts). |

## Quick Start (local, MySQL)

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Fill in `.env`
Make sure the MySQL service is running and `MYSQL_PASSWORD` matches your MySQL user's real
password. An empty/incorrect password is what produces *"Access denied for user 'root'@'localhost'"*
and the "Database error" banner in the admin panel.

### 3. Run the app
```bash
python backend/app.py
```

The app starts on **http://127.0.0.1:5000**. The database `finance_rates` and the `metal_rates`
table are created automatically on startup from `database/schema.sql`.

## Render Deployment

1. Push this repo to GitHub, then create a new Render **Blueprint** (or Web Service) from it.
   `render.yaml` supplies the build/start commands. If you create the service by hand instead,
   leave **Root Directory** blank (`requirements.txt` is in the repo root, `app.py` is in `backend/`) and use:
   - **Build command:** `pip install -r requirements.txt`
   - **Start command:** `gunicorn --chdir backend app:app --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 120`
2. In the service's **Environment** tab, set the values marked `sync: false`:
   - `DATABASE_URL` → your database connection string
     (PostgreSQL: `postgresql://user:password@host:5432/dbname`,
     MySQL: `mysql://user:password@host:3306/dbname`)
   - `ADMIN_USERNAME`, `ADMIN_PASSWORD`
   `FLASK_SECRET_KEY` is generated by Render automatically.
3. Deploy. On the first request the app creates the `metal_rates` table using
   `database/schema_postgres.sql` (PostgreSQL) or `database/schema.sql` (MySQL).
4. The frontend is served by the same service, so `frontend/static/config.json` can keep
   `"apiBase": ""`. Only set `apiBase` to the full Render URL if you host the HTML elsewhere
   (e.g. GitHub Pages).

**Note on GitHub Pages:** it is static only — the Flask admin panel and live API cannot run there.

## Admin Panel Usage

### 1. Access Admin Login
Open browser to: **http://127.0.0.1:5000/admin**

### 2. Login Credentials
Whatever you set in `.env` as `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

### 3. Enter Metal Rates
The admin panel now accepts separate rates for:
- **24K Gold** (per gram in ₹)
- **22K Gold** (per gram in ₹)
- **18K Gold** (per gram in ₹)
- **Silver** (per gram in ₹)
- **Platinum** (per gram in ₹)

### 4. Submit Rates
- Click "Save Rates"
- You'll see a success message
- The rates now appear on the public website

## Database

**Database Name:** `finance_rates`

**Table:** `metal_rates`
```sql
CREATE TABLE metal_rates (
    id INT PRIMARY KEY,
    gold_24k DECIMAL(12,2) NULL,
    gold_22k DECIMAL(12,2) NULL,
    gold_18k DECIMAL(12,2) NULL,
    silver_per_gram DECIMAL(12,2) NULL,
    platinum_per_gram DECIMAL(12,2) NULL,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

## Troubleshooting

### Error: "Access denied for user 'root'@'localhost'"
- The `MYSQL_PASSWORD` in `.env` does not match your MySQL user's password (an empty value gives
  *"using password: NO"*)
- Ensure the MySQL service is running and `MYSQL_HOST` / `MYSQL_PORT` are `localhost` / `3306`

### Error: "Database error (MySQL/PostgreSQL): ..." in the admin panel
The banner now shows the driver's actual reason. Common causes:
- Wrong or missing `DATABASE_URL` / `MYSQL_*` values in `.env` (or in Render's Environment tab)
- Database server not running, or not reachable from Render (use the **external** connection
  string, and allow Render's outbound IPs if your provider has an IP allowlist)
- `DATABASE_URL` set to a `postgresql://` URL while `psycopg2-binary` is not installed
- The connection is refused without TLS → set `MYSQL_SSL=1` or append `?sslmode=require`

The app no longer stays broken after a failed startup: if the database was down when it booted,
the schema init is retried automatically on the next request.

### Admin login rejects the correct password
`ADMIN_USERNAME` / `ADMIN_PASSWORD` are not set, or the app was started before `.env` existed.

### Logged out immediately after logging in
`FLASK_SECRET_KEY` is not set, so each worker process signs cookies with a different random key.

### Rates not showing on public site
- Ensure you logged in with correct credentials
- Verify you clicked "Save Rates" button
- Check admin panel shows last updated timestamp
- Refresh the public website in browser
